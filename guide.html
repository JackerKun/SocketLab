02

连接服务器

先确定页面环境，再选择 WS 或 WSS。

基础连接

  1. 1
    输入服务地址

    例如 wss://example.com/socket?token=abc。省略协议时会自动补充 ws://。

  2. 2
    检查页面协议

    HTTPS 页面必须连接 wss://，否则浏览器会阻止请求。

  3. 3
    点击建立连接

    状态变为 OPEN 后，消息发送功能会自动启用。

服务器地址
WSSwss://example.com/socket
状态OPEN协议默认在线时长00:12:36

高级连接设置

子协议

多个值使用英文逗号分隔，例如 graphql-ws, chat。

连接超时

超过指定毫秒数仍未建立连接时，主动结束本次尝试。

二进制类型

选择以 ArrayBuffer 或 Blob 接收二进制消息。

断线重连

连接异常结束后使用指数退避重试，最长等待 30 秒。

!
浏览器不能设置自定义握手 Header

Token 鉴权请使用 Cookie、URL 参数或 WebSocket 子协议。URL 中不要放置长期有效的敏感 Token。

06

部署与 WSS

GitHub Pages 用户最容易遇到的问题。

BLOCKED · MIXED CONTENT
The page at https://... requested insecure content from
ws://192.168.1.140:5010/. This content was blocked.

HTTPS 页面不能连接明文 ws://。GitHub Pages 默认使用 HTTPS，因此目标服务必须提供 wss://，或改为通过局域网 HTTP 页面使用 SocketLab。

✓http:// 页面→ws:// 服务可连接
✓https:// 页面→wss:// 服务推荐
×https:// 页面→ws:// 服务浏览器阻止

推荐：通过 Caddy 提供 WSS

Caddyfile
ws.example.com {
    reverse_proxy 127.0.0.1:5010
}

然后在 SocketLab 中使用 wss://ws.example.com/?token=1。如果目标是私有 IP，可在局域网通过 HTTP 打开 SocketLab，或使用内部 CA，并让每台客户端信任根证书。

!
仅修改 ws 为 wss 无法解决问题

服务端或反向代理必须真正启用 TLS，并提供与访问域名匹配、受浏览器信任的证书。完整 Caddy、Nginx 和局域网方案请查看 README 部署章节。

08

常见故障排查

从浏览器、代理和服务端三端同时确认。

为什么一直显示 CONNECTING？+

检查地址和端口是否可达、服务端是否监听、证书是否有效，以及 HTTPS 页面是否错误连接了 ws://。浏览器 WebSocket 错误信息较少，应同时查看开发者工具和服务端日志。

为什么连接后立即出现 1006？+

1006 表示异常断开，常见原因包括 TLS 握手失败、代理没有正确转发 Upgrade、服务端异常或网络中断。

为什么 Nginx 返回 400 或 502？+

400 常见于 Upgrade Header 没有转发；502 表示代理无法连接后端，请检查 proxy_pass、监听地址、容器网络和防火墙。

为什么过一段时间自动断开？+

代理可能设置了空闲超时。增加 Nginx 的 proxy_read_timeout，并让服务端定期发送 WebSocket Ping 或业务心跳。

为什么不能添加 Authorization Header？+

浏览器原生 WebSocket API 不允许自定义握手 Header。请改用 HttpOnly Cookie、短期 URL Token 或 WebSocket 子协议。
